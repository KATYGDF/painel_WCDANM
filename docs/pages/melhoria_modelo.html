Melhoria do Modelo — Inicialização do EM e Bootstrap LRT

Quando a sobredispersão é alta e os grupos latentes se sobrepõem, os critérios penalizados clássicos (AIC, BIC, ICL) subestimam sistematicamente o número de componentes. Esta página documenta o experimento controlado que identifica o Bootstrap LRT como o único critério capaz de recuperar a cardinalidade verdadeira nesse cenário, e mostra que — neste caso específico — a escolha da inicialização do EM não importa para a qualidade da solução, apenas para o custo computacional.

1 · Motivação: o problema da sobreposição

A página Análises mostra que a Mistura de Binomial Negativa supera o K-means na recuperação dos grupos latentes em dados multivariados com 5 variáveis. Mas há um cenário onde até a NB enfrenta dificuldade: quando dois grupos têm médias próximas e a sobredispersão é alta, suas distribuições marginais se sobrepõem substancialmente — e o ganho em ajustar um componente extra fica diluído na variabilidade intra-grupo.

É exatamente esse cenário que isolamos aqui em um experimento univariado controlado: apenas a variável consultas, com quatro grupos cujas médias (\(\mu_1 = 2,\ \mu_2 = 12,\ \mu_3 = 25,\ \mu_4 = 50\)) estão espaçadas, mas a dispersão é grande o suficiente (\(\theta = 2{,}5\)) para que G3 (agudo, \(\mu=25\)) e G4 (atípico, \(\mu=50\)) sejam quase indistinguíveis nos dados observados.

Por que isso é uma questão de identificabilidade. A log-verossimilhança da mistura NB é uma função altamente irregular do número de componentes \(g\). Quando dois componentes verdadeiros se sobrepõem, o ganho em log-verossimilhança ao incluir o componente extra é pequeno — e os critérios penalizados (BIC, AIC, ICL) podem julgar esse ganho insuficiente para compensar a penalidade. O modelo escolhido será estável (alto ARI bootstrap), mas com cardinalidade errada.

A pergunta empírica desta página é dupla:

  1. Importa a inicialização? Diferentes pontos de partida do algoritmo EM (random, k-means, CEM, SEM) levam a soluções diferentes em cenário de sobreposição? Em caso positivo, qual é a melhor?
  2. Importa o critério de seleção? AIC, BIC, ICL, AIC3 e Bootstrap LRT — qual deles recupera o número correto de grupos \(g=4\)?

2 · Desenho experimental

O experimento é uma grade fatorial \(4 \times 5 + \text{BLRT}\): quatro estratégias de inicialização cruzadas com cinco valores de \(g\), mais o teste sequencial Bootstrap LRT.

FatorNíveis
Dados \(n=5\,000\) observações simuladas de uma mistura NB com 4 componentes verdadeiros (\(\boldsymbol{\mu} = (2, 12, 25, 50)\), \(\boldsymbol{\pi} = (0{,}25,\ 0{,}25,\ 0{,}25,\ 0{,}25)\), \(\theta = 2{,}5\)).

Cardinalidade \(g \in \{2, 3, 4, 5, 6\}\) (5 valores)
Critérios AIC, BIC, ICL, AIC3, Bootstrap LRT (\(B = 99\))
Estabilidade Bootstrap não-paramétrico via ARI (\(B = 100\))

4 · Estratégias de inicialização

Comparamos quatro estratégias amplamente usadas na literatura. As três primeiras seguem diretamente a comparação de Scharl, Grün & Leisch (2010), que avaliaram oito estratégias no pacote flexmix — o mesmo que usamos aqui.

“The choice of good starting values plays an important role. So far initialization strategies have only been investigated for data from a mixture of multivariate normal distributions. In this work several initialization procedures are evaluated for mixtures of regression models with and without random effects in an extensive simulation study on different artificial datasets.” Scharl, T., Grün, B. & Leisch, F. (2010). Bioinformatics 26(3), 370–377.
Estratégia Mecanismo Referência
Random multistart Vinte execuções de EM completo a partir de partições aleatórias dos rótulos \(z_i \in \{1,\ldots,g\}\); seleciona o ajuste com maior log-verossimilhança final. McLachlan & Peel (2000)
k-means + EM Aplica k-means em \(\log(1+\text{consultas})\), passa a partição resultante como semente do EM completo (uma única execução). Scharl et al. (2010)
CEM + EM Vinte execuções do Classification EM (E-step com atribuição dura, classify="hard"); a melhor solução é refinada por EM completo. Celeux & Govaert (1992)
SEM + EM Vinte execuções do Stochastic EM (E-step amostra rótulos da posterior, classify="random"); a melhor é refinada por EM completo. Celeux & Diebolt (1985)
Por que comparar essas quatro? Cada estratégia exibe um perfil de exploração diferente do espaço de parâmetros: random é o baseline incondicional; k-means impõe uma estrutura geométrica plausível; CEM tende a soluções com componentes bem separados (atribuição dura); SEM escapa de ótimos locais via estocasticidade. Se houver diferenças relevantes entre elas, deveriam aparecer em cenários difíceis como este.

M1 Random multistart

Intuição

O EM é um otimizador local: ele garante chegar a um máximo da log-verossimilhança próximo do ponto onde foi iniciado, mas não garante que seja o máximo global. Para misturas com componentes sobrepostos, a superfície de verossimilhança tem múltiplas modas — e o EM pode parar em qualquer uma delas. A solução mais simples e geral é rodar EM várias vezes a partir de pontos aleatórios diferentes e ficar com o melhor. Com sorte, pelo menos um dos arranques cai na bacia de atração do máximo global.

Algoritmo

Para r = 1, 2, ..., 20:
  1. Sorteie uma partição inicial z⁽⁰⁾ uniforme:
     para cada i ∈ {1,...,n}, atribua z_i ∈ {1,...,g} com prob. 1/g
  2. Inicialize μ_h, π_h a partir dessa partição (M-step inicial)
  3. Itere o EM completo:
        E-step:  τ_ih = π_h · NB(x_i | μ_h, θ) / Σ_l π_l · NB(x_i | μ_l, θ)
        M-step:  π_h = (1/n) Σ_i τ_ih
                 μ_h = Σ_i τ_ih · x_i / Σ_i τ_ih
     até |ℓ⁽ᵗ⁾ − ℓ⁽ᵗ⁻¹⁾| < 1e-7  ou  t = 500
  4. Guarde (ajuste_r, ℓ_r)

Retorne o ajuste com maior ℓ_r.

Prós e contras

✓ Prós ✗ Contras
Funciona em qualquer modelo (NB, Gaussiano, regressão, etc.). É o mais caro — 20× o custo de uma EM única.
Não pressupõe nada sobre a geometria dos dados. Pode falhar se nenhum dos 20 starts cair na bacia certa.
É a referência metodológica clássica (baseline). Shireman et al. (2017): mesmo com 30 starts, pmax ≈ 0,55.
No nosso experimento. Atingiu a maior log-verossimilhança para todo g — mas a um custo enorme: 80 s para g=3, 99 s para g=4, contra 1,6 s do k-means para o mesmo resultado. É a evidência empírica de que neste problema o EM não está preso — então o gasto da exploração é desnecessário.

M2 k-means + EM

Intuição

Em vez de partir de pontos aleatórios, usa um cluster geométrico rápido como ponto de partida informado. O k-means é uma heurística de minimização de soma de quadrados intra-cluster, computacionalmente trivial. Se os componentes verdadeiros da mistura forem grosseiramente separáveis no espaço Euclidiano, o k-means já entrega uma partição "quase certa", e o EM só precisa refinar.

A transformação \(\log(1+x)\) é importante: contagens cruas têm variância proporcional à média (comportamento Poisson-like), então valores grandes dominam a distância Euclidiana. O log1p aproxima homocedasticidade — sem ele, o k-means viraria essencialmente um teste para "está acima ou abaixo de tal valor", desprezando a estrutura dos componentes pequenos.

Algoritmo

1. Aplique k-means nos dados log-transformados:
     z⁽⁰⁾ = kmeans(log(1 + x),
                   centers = g,
                   nstart  = 25,        # 25 reinícios internos do próprio k-means
                   iter.max = 100)$cluster

2. Use z⁽⁰⁾ como partição inicial do EM completo (uma única execução):
     iterar E-step / M-step até convergência

3. Retorne o ajuste único.

Prós e contras

✓ Prós ✗ Contras
~50× mais rápido que random multistart. Pressupõe geometria esférica e equi-tamanho — viés se a mistura tiver componentes muito assimétricos.
Determinístico (dada a semente). Pode falhar quando componentes se sobrepõem fortemente no espaço euclidiano.
Boa partida quando há separação geométrica clara. A geometria do k-means não casa naturalmente com a forma da NB (cauda longa).
No nosso experimento. O grande vencedor pragmático. Atingiu exatamente a mesma log-verossimilhança do random multistart em todos os g, mas em ~1,6 s em vez de ~80 s. Isso indica que, neste problema, o EM já é bem comportado — e a sofisticação da exploração random não compra qualidade extra.

M3 CEM + EM (Classification EM)

Intuição

O EM padrão faz atribuição soft: cada observação contribui para todos os componentes proporcionalmente à sua probabilidade posterior. O CEM faz atribuição dura: cada observação é atribuída ao componente mais provável, e só ele aprende com aquela observação.

Isso muda o que está sendo otimizado: o EM maximiza a log-verossimilhança observada dos dados; o CEM maximiza a log-verossimilhança completa (assumindo as atribuições como conhecidas). Tipicamente, CEM converge mais rápido e produz componentes mais separados — mas pode colapsar componentes pequenos.

Algoritmo

Para r = 1, 2, ..., 20:
  1. Partição inicial aleatória z⁽⁰⁾
  2. Itere o CEM:
        E-step (hard):  ẑ_i = argmax_h τ_ih       # atribuição DURA
        M-step:         π_h, μ_h estimados usando SÓ as obs com ẑ_i = h
     até partição estabilizar  ou  t = 100
  3. Guarde (ajuste_r, ℓ_r)

Escolha o melhor CEM (maior ℓ_r).
Refine com EM completo (classify = "weighted").
Retorne o ajuste refinado.

Prós e contras

✓ Prós ✗ Contras
Convergência mais rápida por iteração. Frágil para componentes pequenos: se < ~5% das observações caem num componente em uma iteração, ele colapsa.
Produz componentes bem separados (útil em alguns contextos). Sob sobredispersão alta, a atribuição dura é arbitrária para obs na zona de sobreposição.
Matematicamente bem definido (Celeux & Govaert, 1992). Tende a subestimar g quando há sobreposição real.
No nosso experimento. Falhou em 3 das 5 cardinalidades (g = 4, 5, 6). O motivo: com θ = 2,5, G3 e G4 se sobrepõem tanto que a atribuição dura é praticamente um sorteio, e qualquer flutuação leva ao colapso do componente menor — o CEM não consegue manter 4 componentes vivos no mesmo ajuste. Confirma a fragilidade conhecida do método em contagens sobredispersas.

M4 SEM + EM (Stochastic EM)

Intuição

O SEM resolve o problema do CEM (colapso por atribuição dura) introduzindo aleatoriedade: em vez de escolher o componente mais provável, ele sorteia o componente de cada observação proporcionalmente à sua probabilidade posterior. Cada iteração resulta em uma partição diferente — o método se torna uma cadeia de Markov no espaço de parâmetros.

A vantagem teórica: a aleatoriedade dá ao algoritmo um mecanismo para escapar de máximos locais — se o EM ficaria preso num ótimo local pobre, o sorteio estocástico tende, com o tempo, a deslocá-lo para regiões de maior verossimilhança.

Algoritmo

Para r = 1, 2, ..., 20:
  1. Partição inicial aleatória z⁽⁰⁾
  2. Itere o SEM:
        E-step (stochastic):  ẑ_i ~ Multinomial(τ_i1, ..., τ_ig)
        M-step:               π_h, μ_h estimados com ẑ sorteado
     até log-verossimilhança estabilizar  ou  t = 100
  3. Guarde o melhor ponto da trajetória

Escolha o melhor SEM. Refine com EM completo. Retorne o ajuste refinado.

Diferença crucial em relação ao CEM: o SEM não converge para um ponto fixo — ele oscila numa distribuição estacionária. Na prática, usa-se o ponto da trajetória com maior log-verossimilhança (ou a média dos últimos passos).

Prós e contras

✓ Prós ✗ Contras
Aleatoriedade ajuda a escapar de ótimos locais. Convergência mais ruidosa que CEM ou EM.
Adequado quando há suspeita de múltiplos máximos locais. Ainda sujeito ao colapso de componentes pequenos (sorteio pode dar zero por azar).
Dá uma noção empírica de incerteza dos parâmetros. Mais lento que CEM por causa do ruído.
No nosso experimento. Falhou em g = 5 (componente colapsou no sorteio). Para g ∈ {2, 3, 4, 6} chegou ao mesmo máximo dos outros métodos, mas com custo intermediário (~25 s vs 1,6 s do k-means). Confirma que neste problema não há múltiplos ótimos locais relevantes para fugir — então a estocasticidade do SEM não compra benefício, só acrescenta variância.

5 · Critérios de seleção de componentes

Para cada combinação inicialização × g calculamos quatro critérios penalizados clássicos e o Bootstrap LRT sequencial:

Critério Fórmula Penalidade
AIC \(-2\ell + 2p\) Linear em \(p\) (parâmetros). Tende a superestimar \(g\).
BIC \(-2\ell + p \log n\) Cresce com \(n\). Padrão de fato em misturas finitas.
AIC3 \(-2\ell + 3p\) Compromisso entre AIC e BIC. Sugerido por Bozdogan para misturas.
ICL \(\text{BIC} - 2 \sum_{i,k} \hat z_{ik} \log \hat z_{ik}\) BIC + penalidade pela entropia da classificação. Favorece componentes bem separados.
Bootstrap LRT Teste \(H_0\!: g\) vs \(H_1\!: g+1\) via reamostragem paramétrica Calibração empírica da distribuição nula do LRT. Não-assintótica.

O ICL e o BLRT merecem nota especial.

ICL — Integrated Completed Likelihood. Biernacki, Celeux & Govaert (2000) propuseram o ICL como BIC com uma penalidade adicional pela entropia das probabilidades posteriores. Quando os componentes estão bem separados, as posteriores são próximas de \(\{0,1\}\) e a entropia é baixa — ICL converge para BIC. Quando os componentes se sobrepõem, as posteriores ficam difusas, a entropia explode, e o ICL penaliza fortemente — preferindo modelos com menos componentes. Isto é uma virtude em alguns contextos, mas uma vulnerabilidade quando a sobreposição é a própria estrutura do problema.
Bootstrap LRT. Em misturas finitas, a estatística \(2(\ell_{g+1} - \ell_g)\) não segue \(\chi^2\) sob \(H_0\) — as condições de regularidade de Wilks são violadas porque o parâmetro adicional fica na fronteira do espaço (peso zero) quando \(g\) é verdadeiro. A solução de McLachlan (1987) é simular a distribuição nula empiricamente: gerar \(B\) amostras paramétricas sob o modelo de \(g\) componentes ajustado, recalcular o LRT para cada uma, e comparar o LRT observado contra essa distribuição empírica.

6 · Resultados — Módulo A · Inicializações

A Tabela 1 reporta log-verossimilhança, BIC, ICL, AIC e tempo computacional para todas as 20 combinações inicialização × g. A Figura 2 mostra a mesma informação graficamente.

Tabela 1. log-verossimilhança, critérios penalizados e tempo por estratégia de inicialização e \(g\). Cor de fundo na coluna BIC: verde = menor (melhor), vermelho = maior. CEM falha para \(g \geq 4\) e SEM falha para \(g=5\) (componentes colapsam).

Figura 2. log-verossimilhança em função de \(g\) para cada estratégia. As quatro linhas se sobrepõem quase perfeitamente quando o ajuste converge — todas as inicializações encontram o mesmo máximo global. A queda visível entre \(g=2\) e \(g=3\) reflete a separação real entre G1+G2 e o continuum G3/G4; entre \(g=3\) e \(g=4\) o ganho é praticamente nulo.

Análise da Figura 2

Três fatos saltam aos olhos:

  1. As quatro estratégias se sobrepõem. Para cada \(g\), a log-verossimilhança máxima atingida é praticamente idêntica nas quatro inicializações (diferenças \(< 0{,}4\) unidades, dentro de ruído numérico). Isto significa que o EM não fica preso em ótimos locais neste problema — todos os pontos de partida convergem para a mesma solução.
  2. O ganho de \(g=3\) para \(g=4\) é minúsculo (1,4 unidades de log-verossimilhança com \(n=5\,000\)). É essa magnitude que vai determinar o destino de cada critério penalizado: BIC penaliza \(\log(5000)/2 \approx 4{,}26\) por parâmetro, e \(g=3 \to g=4\) adiciona 2 parâmetros (1 média + 1 peso) — penalidade total \(\approx 8{,}5\), maior que o ganho de 2,8 em \(-2\ell\). BIC vai rejeitar.
  3. CEM falha em três das cinco cardinalidades (g = 4, 5, 6). A atribuição dura do CEM colapsa componentes pequenos sob sobredispersão alta — confirmando uma fragilidade conhecida do método em dados de contagem.
Achado A1 Inicialização não afeta a qualidade neste problema. Random, k-means e SEM+EM atingem a mesma log-verossimilhança máxima para todo \(g\) testado. O desafio do problema é de identificabilidade, não de otimização.
Achado A2 k-means é ~50× mais rápido que random multistart com qualidade idêntica (\(g=3\): 1,6 s vs 80,5 s; \(g=4\): 1,6 s vs 98,8 s). É a escolha prática de partida — escalar para random multistart só se houver suspeita de ótimo local.
“Random initialization yields very long runtimes compared with CEM or short runs of EM. However, the cluster results are similar.” Scharl, Grün & Leisch (2010), conclusão #4 do estudo de simulação.
“The impact of the cluster method used is much larger than the impact of the initialization strategy.” Scharl, Grün & Leisch (2010), conclusão #5.

Nosso experimento corrobora empiricamente a observação canônica do Scharl et al. (2010): no caso em que o EM converge sem ficar preso, a estratégia de inicialização é praticamente irrelevante para a qualidade da solução, importando apenas para o custo computacional.

7 · Resultados — Módulo B · Critérios penalizados

Tomando a melhor inicialização por \(g\) (em todos os casos: random ou k-means — empatados em log-verossimilhança), aplicamos os quatro critérios penalizados. A Tabela 2 e a Figura 3 mostram o resultado.

Tabela 2. Critérios de seleção avaliados na melhor inicialização para cada \(g\). A coluna Selecionado por indica quais critérios escolhem cada \(g\) como ótimo. A linha destacada em amarelo é o \(g\) final por consenso de votos (3).

Figura 3. Os quatro critérios penalizados, normalizados para o intervalo [0, 1] (0 = melhor, 1 = pior) para permitir comparação visual. Linha tracejada cinza marca \(g=4\) (verdade). Nenhum critério penalizado consegue identificar o \(g\) verdadeiro: AIC/BIC/AIC3 escolhem \(g=3\); ICL escolhe \(g=2\) (ainda mais conservador).

Análise da Figura 3

Os mínimos de cada curva são autoexplicativos:

  • BIC, AIC, AIC3 → \(g=3\): os três concordam em incluir o componente que separa o continuum G3/G4 da moda central (G1, G2), mas nenhum considera vantajoso dividir esse continuum em dois grupos separados. O ganho de log-verossimilhança não vence a penalidade.
  • ICL → \(g=2\): mais conservador ainda. A penalidade adicional pela entropia da classificação cresce monotonicamente com \(g\) porque, conforme adicionamos componentes que se sobrepõem aos existentes, as posteriores ficam mais difusas. ICL é, em termos práticos, monótono crescente neste cenário — qualquer \(g > 2\) é penalizado.
Alerta metodológico: o ICL é frequentemente recomendado como alternativa ao BIC quando há sobreposição entre componentes. O experimento aqui mostra exatamente o oposto: quando a sobreposição é a estrutura real do problema (e não um artefato), o ICL é muito conservador. Use ICL apenas quando houver razão substantiva para acreditar em componentes bem separados.

8 · Resultados — Módulo C · Bootstrap LRT

O teste paramétrico de razão de verossimilhança via bootstrap (McLachlan, 1987) é a única alternativa que não depende de aproximações assintóticas. Para cada par \((g, g+1)\), simulamos \(B=99\) amostras de tamanho \(n=5\,000\) sob o modelo ajustado com \(g\) componentes, recalculamos o LRT em cada uma, e construímos o p-valor empírico \(p = (\#\{\text{LRT}^{(b)} \geq \text{LRT}_\text{obs}\} + 1)/(B+1)\).

Tabela 3. Bootstrap LRT sequencial. A linha em amarelo (\(g=4 \to 5\), p = 0,57) é onde o teste deixa de rejeitar \(H_0\), fixando \(g^* = 4\).

Figura 4. Quatro distribuições bootstrap da estatística LRT sob \(H_0\), uma para cada par \((g, g+1)\). A linha vermelha tracejada marca o LRT observado nos dados reais. Note como em \(g=2 \to 3\) e \(g=3 \to 4\) o LRT observado está na cauda direita (p < 0,05); em \(g=4 \to 5\) e \(g=5 \to 6\) o LRT observado é praticamente zero, consistente com a distribuição nula.

Análise da Figura 4

Os quatro paineis revelam um padrão que justifica integralmente o uso do BLRT em vez do χ² assintótico:

  • \(g=2 \to 3\): LRT observado = 306,9. Distribuição bootstrap fortemente concentrada perto de zero. \(p=0{,}01\) → rejeita \(H_0\). Há um terceiro componente.
  • \(g=3 \to 4\): LRT observado = apenas 2,8 — extraordinariamente pequeno. Mas a distribuição bootstrap sob \(H_0\) está ainda mais comprimida (a maioria dos LRTs replicados fica abaixo de 1). Resultado: \(p=0{,}04\) → rejeita \(H_0\). Há um quarto componente.
  • \(g=4 \to 5\): LRT observado ≈ 0, p = 0,57 → não rejeita. \(g=4\) é suficiente.
  • \(g=5 \to 6\): idem (p = 0,47), confirmando o teto.
Achado C1 O BLRT é o único critério que recupera \(g=4\). Ele detecta um ganho de log-verossimilhança de apenas 2,8 unidades como significativo porque a distribuição empírica de LRT sob \(H_0\) é ainda mais concentrada em zero — uma estrutura que a aproximação χ²(df) ignora por completo.
“The likelihood ratio statistic \(-2\log\lambda\) does not have its usual asymptotic null distribution of chi-squared with the difference in the number of parameters under the two hypotheses, owing to the breakdown of the standard regularity conditions for the chi-squared approximation.” McLachlan, G. J. (1987). Journal of the Royal Statistical Society Series C, 36(3), 318–324.

9 · Resultados — Módulo D · Modelo final e estabilidade

Tomando o voto majoritário entre os cinco critérios (AIC=3, BIC=3, AIC3=3, ICL=2, BLRT=4), o consenso seria \(g=3\). Avaliamos a estabilidade desse modelo por bootstrap não-paramétrico: reamostramos com reposição \(B=100\) vezes, reajustamos a mistura com \(g=3\), e calculamos o ARI entre a partição original e a do bootstrap.

Figura 5. Distribuição bootstrap do Adjusted Rand Index entre a partição original (\(g=3\)) e as partições obtidas em \(B=100\) reamostragens. ARI médio = 0,894, IC 95% [0,724; 1,000]. Limiar usual de estabilidade (0,80) marcado em laranja. O modelo \(g=3\) é estavelmente reproduzido sob reamostragem.

Atenção interpretativa: ARI = 0,894 é alto, mas isso significa que o modelo \(g=3\) é consistentemente o mesmo modelo errado, não que \(g=3\) seja a cardinalidade correta. Estabilidade de partição não é evidência de cardinalidade correta — é apenas evidência de que o procedimento converge para a mesma solução em reamostragens. Quando o critério de seleção subestima \(g\), a partição resultante pode ser perfeitamente estável e completamente equivocada.

Figura 6. Modelo final por consenso (\(g=3\), inicialização random) sobreposto ao histograma dos dados. As três linhas coloridas são as componentes NB ajustadas; a linha preta tracejada é a mistura total. A terceira componente é uma fusão de G3 e G4 verdadeiros — consistente com a interpretação de que BIC/AIC/ICL não conseguiram separar o continuum de cauda direita.

10 · Sete conclusões metodológicas

Cada conclusão é apoiada empiricamente nos resultados acima e referenciada na literatura quando aplicável.

Conclusão 1 O problema é de identificabilidade, não de otimização. As quatro estratégias de inicialização chegaram ao mesmo máximo da log-verossimilhança para todo \(g\). O obstáculo está na paisagem da verossimilhança em si: o ganho de \(g=3\) para \(g=4\) é apenas 1,4 unidades, pequeno demais para qualquer critério penalizado clássico considerar relevante.
Conclusão 2 k-means inicializa o EM ~50× mais rápido com qualidade equivalente. Para mistura NB univariada deste tipo, sempre comece por k-means. Escalar para random multistart só se houver razão para suspeitar de ótimo local.
Conclusão 3 Bootstrap LRT é o único critério que recupera \(g=4\). Os critérios penalizados clássicos (AIC, BIC, AIC3, ICL) subestimaram sistematicamente. O BLRT detectou \(g=3 \to g=4\) como significativo (p = 0,04) mesmo com ganho de log-verossimilhança ínfimo, porque a distribuição empírica de LRT sob \(H_0\) é mais concentrada em zero do que a aproximação χ² assintótica supõe.
Conclusão 4 CEM é frágil para contagens sobredispersas. CEM+EM falhou em 3 de 5 valores de \(g\) (\(g\) = 4, 5, 6). A classificação dura do CEM colapsa componentes pequenos quando há sobreposição. Não usar CEM como default em mistura NB com θ baixo.
Conclusão 5 ICL é muito conservador em cenários sobrepostos. ICL escolheu \(g=2\), duas categorias abaixo da verdade. A penalidade por entropia da classificação cresce monotonicamente com a sobreposição. ICL é apropriado quando se sabe que os componentes são bem separados — exatamente o oposto deste cenário.
Conclusão 6 Voto majoritário entre critérios falha aqui. Quatro critérios em cinco apontam \(g \leq 3\); apenas o BLRT aponta \(g=4\). A maioria está errada. Lição: quando um critério é especificamente justificado pelo tipo de dado (BLRT para sobreposição com sobredispersão), ele deve ter peso desproporcional — ou ser usado como árbitro final em vez de um voto entre muitos.
Conclusão 7 Estabilidade alta não implica cardinalidade correta. O modelo \(g=3\) tem ARI bootstrap = 0,894 (IC95% [0,724; 1,000]) — altamente estável. Mas está estavelmente errado: funde G3 e G4. Estabilidade de partição mede consistência de reamostragem, não acerto da cardinalidade.

A tabela abaixo consolida o veredito empírico para cada estratégia em três dimensões — qualidade da solução, velocidade e robustez — e indica em que cenário cada uma é a escolha preferencial.

Velocidade ★ ★★★ ★★ ★★
Determinismo ★ ★★★ ★★ ★

Veredito. Quando a paisagem de verossimilhança é bem-comportada (caso comum para misturas NB com n alto e θ moderado), k-means + EM é a escolha que domina: mesma qualidade da solução, fração do custo computacional, totalmente determinístico. Random multistart permanece como apólice de seguro caso haja suspeita de ótimos locais. CEM e SEM são úteis em nichos específicos (componentes muito separados ou múltiplos máximos), mas frágeis em contagens sobredispersas.

11 · Próximos passos

Este experimento fixa um único cenário (\(\theta=2{,}5\), 4 grupos, médias espaçadas). Para fortalecer as conclusões e produzir um experimento factorial publicável, propõem-se três extensões:

  1. Replicar com \(\theta\) variável (e.g., \(\theta \in \{1, 2{,}5, 5, 10\}\)) para mapear o regime em que cada critério quebra. Hipótese: com \(\theta \geq 10\), todos os critérios convergem para \(g=4\); com \(\theta \leq 1\), até o BLRT pode falhar.
  2. Replicar com diferentes espaçamentos de \(\boldsymbol{\mu}\) para isolar o efeito da sobreposição induzida pela proximidade das médias versus pela dispersão.
  3. Adicionar short-EM (Biernacki, Celeux & Govaert, 2003) como quinta estratégia de inicialização (várias execuções curtas de EM, seleciona a melhor, refina com EM completo). Completa a comparação do Scharl et al. (2010).
  4. Repetir réplicas estocásticas (e.g., 30 simulações independentes por configuração) para construir distribuições de \(g^*\) por critério — mostra robustez ou variabilidade dos resultados aqui apresentados.

12.2 · As quatro estratégias de inicialização

Núcleo do experimento. Cada estratégia é uma função que recebe o número de componentes k e retorna o melhor ajuste obtido pela respectiva política de exploração. A função interna fit_um() encapsula a chamada ao flexmix — assim os quatro métodos diferem apenas no argumento classify_mode (modo do E-step) e no número de reinícios. 

# ── Ajuste único (núcleo compartilhado pelas 4 estratégias) ───────────────────
fit_um <- function(cluster_init, k_val, classify_mode = "weighted",
                   seed = 42, iter_max = 500,
                   tolerance = 1e-7, minprior = 0.01) {
  set.seed(seed)
  ctrl <- list(iter.max = iter_max, tolerance = tolerance,
               minprior = minprior, classify = classify_mode)
  args <- list(
    formula = consultas ~ 1, data = df, k = k_val,
    model = FLXMRnegbin(theta = THETA_NB), control = ctrl
  )
  if (!is.null(cluster_init)) args$cluster <- cluster_init
  tryCatch(suppressWarnings(do.call(flexmix, args)),
           error = function(e) NULL)
}

# ── M1 · Random multistart ────────────────────────────────────────────────────
# nrep ajustes EM partindo de partições aleatórias; retorna o melhor logLik.
init_random <- function(k_val, nrep = NREP, seed = 100) {
  best <- NULL; best_ll <- -Inf
  for (i in seq_len(nrep)) {
    fit_i <- fit_um(cluster_init = sample.int(k_val, N, replace = TRUE),
                    k_val = k_val, classify_mode = "weighted",
                    seed = seed + i)
    if (!is.null(fit_i) && fit_i@k == k_val) {
      ll <- as.numeric(logLik(fit_i))
      if (!is.na(ll) && ll > best_ll) { best_ll <- ll; best <- fit_i }
    }
  }
  best
}

# ── M2 · k-means + EM ─────────────────────────────────────────────────────────
# k-means em log(1+x) gera a partição inicial; refina com EM completo (1 run).
init_kmeans <- function(k_val, seed = 200) {
  set.seed(seed)
  if (k_val == 1L) return(fit_um(NULL, 1L, seed = seed))
  km <- kmeans(log1p(df$consultas),
               centers = k_val, nstart = 25, iter.max = 100)
  fit_um(cluster_init = km$cluster, k_val = k_val, seed = seed)
}

# ── M3 · CEM + EM ─────────────────────────────────────────────────────────────
# Classification EM (E-step duro) seguido de refinamento com EM completo.
init_cem_em <- function(k_val, nrep = NREP, seed = 300) {
  best_cem <- NULL; best_ll <- -Inf
  for (i in seq_len(nrep)) {
    fit_i <- fit_um(cluster_init = sample.int(k_val, N, replace = TRUE),
                    k_val = k_val, classify_mode = "hard",    # <- CEM
                    seed = seed + i,
                    iter_max = 100, tolerance = 1e-5)
    if (!is.null(fit_i) && fit_i@k == k_val) {
      ll <- as.numeric(logLik(fit_i))
      if (!is.na(ll) && ll > best_ll) { best_ll <- ll; best_cem <- fit_i }
    }
  }
  if (is.null(best_cem)) return(NULL)
  fit_um(cluster_init = clusters(best_cem), k_val = k_val,
         classify_mode = "weighted", seed = seed)   # refinamento EM
}

# ── M4 · SEM + EM ─────────────────────────────────────────────────────────────
# Stochastic EM (E-step amostra) seguido de refinamento com EM completo.
init_sem_em <- function(k_val, nrep = NREP, seed = 400) {
  best_sem <- NULL; best_ll <- -Inf
  for (i in seq_len(nrep)) {
    fit_i <- fit_um(cluster_init = sample.int(k_val, N, replace = TRUE),
                    k_val = k_val, classify_mode = "random",  # <- SEM
                    seed = seed + i,
                    iter_max = 100, tolerance = 1e-5)
    if (!is.null(fit_i) && fit_i@k == k_val) {
      ll <- as.numeric(logLik(fit_i))
      if (!is.na(ll) && ll > best_ll) { best_ll <- ll; best_sem <- fit_i }
    }
  }
  if (is.null(best_sem)) return(NULL)
  fit_um(cluster_init = clusters(best_sem), k_val = k_val,
         classify_mode = "weighted", seed = seed)
}

12.3 · Critérios penalizados e Bootstrap LRT

extrair_metricas() calcula AIC, BIC, ICL e AIC3 a partir de um ajuste do flexmix. simular_nb_mistura() gera amostras paramétricas sob o modelo ajustado (necessário para o bootstrap). blrt_passo() executa o teste de razão de verossimilhança bootstrap para um par (k, k+1). 

# ── Critérios penalizados a partir de um fit ──────────────────────────────────
extrair_metricas <- function(fit) {
  if (is.null(fit)) return(NULL)
  ll <- as.numeric(logLik(fit))
  np <- attr(logLik(fit), "df")
  list(
    k_efetivo = fit@k,
    logLik    = round(ll, 2),
    np        = np,
    AIC       = round(-2 * ll + 2 * np, 2),
    BIC       = round(-2 * ll + np * log(N), 2),
    ICL       = round(ICL(fit), 2),
    AIC3      = round(-2 * ll + 3 * np, 2)
  )
}

# ── Bootstrap paramétrico sob H0: k0 componentes ──────────────────────────────
simular_nb_mistura <- function(fit, n_sim, theta_fixo = THETA_NB) {
  pesos <- prior(fit); pars <- as.numeric(parameters(fit)); k <- fit@k
  log_mus <- pars; thetas <- rep(theta_fixo, k)
  comp <- sample.int(k, size = n_sim, replace = TRUE, prob = pesos)
  y <- integer(n_sim)
  for (h in seq_len(k)) {
    idx <- which(comp == h)
    if (length(idx)) y[idx] <- rnbinom(length(idx),
                                          size = thetas[h],
                                          mu = exp(log_mus[h]))
  }
  y
}

# ── BLRT: H0: k vs H1: k+1 ────────────────────────────────────────────────────
# Distribuição nula obtida empiricamente por reamostragem paramétrica.
blrt_passo <- function(fit_k0, fit_k1, B = BLRT_B, nrep = BLRT_NREP, seed = 1000) {
  set.seed(seed)
  k0 <- fit_k0@k; k1 <- fit_k1@k
  lrt_obs <- 2 * (as.numeric(logLik(fit_k1)) - as.numeric(logLik(fit_k0)))

  ll_best_k <- function(df_b, k_val) {
    best <- -Inf
    for (i in seq_len(nrep)) {
      m <- tryCatch(suppressWarnings(flexmix(
        consultas ~ 1, data = df_b, k = k_val,
        model = FLXMRnegbin(theta = THETA_NB),
        control = list(iter.max = 200, minprior = 0.01, tolerance = 1e-6)
      )), error = function(e) NULL)
      if (!is.null(m) && m@k == k_val) {
        ll <- as.numeric(logLik(m))
        if (!is.na(ll) && ll > best) best <- ll
      }
    }
    if (is.infinite(best)) NA_real_ else best
  }

  lrt_b <- vapply(seq_len(B), function(b) {
    y_b <- simular_nb_mistura(fit_k0, N)
    df_b <- data.frame(consultas = y_b)
    ll0 <- ll_best_k(df_b, k0); ll1 <- ll_best_k(df_b, k1)
    if (anyNA(c(ll0, ll1))) NA_real_ else 2 * (ll1 - ll0)
  }, numeric(1))

  lrt_v <- lrt_b[!is.na(lrt_b)]
  pval <- (sum(lrt_v >= lrt_obs) + 1) / (length(lrt_v) + 1)
  list(k0 = k0, k1 = k1, lrt_obs = round(lrt_obs, 2),
       pval = round(pval, 4), B_valido = length(lrt_v), lrt_boot = lrt_v)
}

12.4 · Loop principal — grade Inicialização × k

O laço que materializa o experimento factorial: para cada combinação estratégia × g, ajusta o modelo, extrai métricas e armazena o fit. O resultado é o objeto fits (lista aninhada de ajustes) e a tabela tab_init usada para gerar a Figura 2 e a Tabela 1 da página. 

# ── Lista das 4 estratégias ───────────────────────────────────────────────────
INITS <- list(
  random = init_random,
  kmeans = init_kmeans,
  cem_em = init_cem_em,
  sem_em = init_sem_em
)

fits     <- setNames(vector("list", length(INITS)), names(INITS))
tab_init <- list()

for (init_nm in names(INITS)) {
  fits[[init_nm]] <- setNames(vector("list", length(K_GRID)),
                              as.character(K_GRID))
  for (k_val in K_GRID) {
    cat(sprintf("  %-8s k=%d ... ", init_nm, k_val))
    t0 <- proc.time()["elapsed"]
    fit_kv <- INITS[[init_nm]](k_val)               # <- ajusta usando a estratégia
    dt <- proc.time()["elapsed"] - t0
    fits[[init_nm]][[as.character(k_val)]] <- fit_kv
    m <- extrair_metricas(fit_kv)               # <- coleta AIC/BIC/ICL/AIC3
    if (is.null(m)) {
      cat(sprintf("FALHOU (%.1fs)\n", dt))
      tab_init[[length(tab_init) + 1]] <- data.frame(
        init = init_nm, k = k_val, k_efetivo = NA, logLik = NA, np = NA,
        AIC = NA, BIC = NA, ICL = NA, AIC3 = NA, tempo_s = round(dt, 1))
    } else {
      cat(sprintf("logLik=%.1f | BIC=%.1f | %.1fs\n", m$logLik, m$BIC, dt))
      tab_init[[length(tab_init) + 1]] <- data.frame(
        init = init_nm, k = k_val,
        k_efetivo = m$k_efetivo, logLik = m$logLik, np = m$np,
        AIC = m$AIC, BIC = m$BIC, ICL = m$ICL, AIC3 = m$AIC3,
        tempo_s = round(dt, 1))
    }
  }
}

tab_init <- do.call(rbind, tab_init)
