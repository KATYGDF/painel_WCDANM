Seleção do número de componentes

Por que BIC e ICL não bastam — e como o BLRT preenche essa lacuna · experimento controlado com mistura NB, k = 4, theta = 2,5

1 · O problema de identificar \(k\)

Em um modelo de mistura finita com \(k\) componentes Binomial Negativa, a densidade de cada observação \(y_i\) é:

$$f(y_i \mid \boldsymbol{\Psi}) = \sum_{g=1}^{k} \pi_g \; f_{\text{NB}}(y_i \mid \mu_g, \theta_g)$$

Dado que \(k\) é desconhecido, o problema de seleção consiste em escolher o valor que melhor representa a estrutura real da população — nem pequeno demais (fundindo grupos distintos) nem grande demais (fragmentando grupos reais em artefatos do ajuste).

A dificuldade central é que a log-verossimilhança cresce monotonicamente com \(k\): adicionar uma componente sempre melhora o ajuste, mesmo que o grupo extra não corresponda a nenhuma estrutura real. Qualquer critério precisa portanto penalizar a complexidade — e a questão é como fazê-lo corretamente.

2 · Critérios de informação: BIC e ICL

BIC — Bayesian Information Criterion

O BIC (Schwarz, 1978) é o critério mais utilizado em modelos de mistura. Para um modelo com \(p\) parâmetros livres ajustado a \(n\) observações:

$$\text{BIC} = -2\,\ell(\hat{\boldsymbol{\Psi}}) + p \cdot \log(n)$$

A penalidade \(p \cdot \log(n)\) cresce com a amostra, tornando o BIC consistente em contextos regulares. Nylund, Asparouhov e Muthén (2007) demonstraram por simulação extensiva que o BIC supera o AIC para seleção de \(k\) — mas com ressalva importante:

"The BIC performed well across conditions, but there were notable exceptions. When class separation was low and sample sizes were small, BIC tended to underestimate the number of classes." Nylund, Asparouhov & Muthén (2007, p. 554) · Structural Equation Modeling, 14(4), 535–569

O mecanismo é aritmético: quando dois grupos se sobrepõem muito, o ganho em log-verossimilhança ao distingui-los é pequeno. Se esse ganho for menor que a penalidade \(\log(n)\) por parâmetro adicional, o BIC prefere o modelo mais simples — mesmo que o grupo extra seja real.

ICL — Integrated Complete-data Likelihood

O ICL (Biernacki, Celeux & Govaert, 2000) adiciona ao BIC uma penalidade baseada na entropia das probabilidades posteriores:

$$\text{ICL} = \text{BIC} - 2 \sum_{i=1}^{n} \sum_{g=1}^{k} \hat{z}_{ig} \log \hat{z}_{ig}$$

Quando as probabilidades posteriores são próximas de 0 ou 1 (classificação clara), o segundo termo é pequeno e ICL ≈ BIC. Quando há sobreposição intensa, \(\hat{z}_{ig} \approx 1/k\) para muitos indivíduos, a entropia é máxima e o ICL penaliza fortemente.

"The ICL criterion favors models for which a partition of the data based on MAP classification is well-defined. It therefore tends to select models with well-separated components." Biernacki, Celeux & Govaert (2000, p. 720) · IEEE Trans. Pattern Anal. Mach. Intell., 22(7), 719–725

Na prática, o ICL subestima \(k\) sistematicamente quando os grupos se sobrepõem. Para dados de utilização em saúde, o ICL funciona melhor como indicador do grau de sobreposição do que como seletor de \(k\).

Evidência nesta tese: na simulação com \(k=4\), \(\theta=2{,}5\) (alta superdispersão), o BIC apontou \(k=3\) e o ICL atingiu mínimo em \(k=2\) (42 227), crescendo monotonicamente até \(k=8\) (51 198) — nenhum \(k > 2\) produzia separação suficiente para o ICL. Ambos subestimaram \(k=4\), cada um por motivo diferente.

3 · A quebra do LRT clássico em misturas

A solução natural para testar \(k\) versus \(k+1\) seria o teste da razão de verossimilhança (LRT):

$$\Lambda = -2\left[\ell(\hat{\boldsymbol{\Psi}}_{k}) - \ell(\hat{\boldsymbol{\Psi}}_{k+1})\right]$$

Em condições regulares, \(\Lambda \xrightarrow{d} \chi^2_\nu\) sob \(H_0\), com \(\nu\) graus de liberdade iguais à diferença no número de parâmetros. O problema é que, para misturas, as condições de regularidade do teorema de Wilks não valem.

Sob \(H_0: k = k_0\), o parâmetro de mistura da componente extra é identificável apenas na fronteira do espaço paramétrico (onde \(\pi_{k+1} = 0\)), e os pesos das componentes estão na fronteira do simplex. Isso viola duas condições do teorema de Wilks: que o verdadeiro parâmetro seja interior ao espaço e que o modelo seja identificável sob \(H_0\).

"When testing for the number of components in a finite mixture model, the usual asymptotic theory for the likelihood ratio statistic does not apply, and so its null distribution cannot be taken to be chi-squared." McLachlan & Peel (2000, p. 194) · Finite Mixture Models. Wiley

A consequência é grave: p-valores de \(\chi^2\) para o LRT em misturas produzem taxas de erro tipo I incontroláveis. A distribuição real do LRT sob \(H_0\) é mais pesada na cauda direita — os testes clássicos são liberais demais.

4 · O BLRT: Bootstrap Likelihood Ratio Test

Se a distribuição assintótica do LRT não pode ser derivada analiticamente, ela pode ser aproximada empiricamente — simulando qual seria a distribuição do LRT se \(H_0\) fosse verdadeira. Essa é a ideia do BLRT, proposto por McLachlan (1987) e sistemizado para análise de classes latentes por Nylund et al. (2007).

O algoritmo em cinco passos

Passo 1. Ajustar o modelo com \(k_0\) componentes (\(H_0\)) e com \(k_1 = k_0 + 1\) componentes (\(H_1\)) aos dados originais. Calcular:

$$\Lambda_\text{obs} = -2\left[\ell(\hat{\boldsymbol{\Psi}}_{k_0}) - \ell(\hat{\boldsymbol{\Psi}}_{k_1})\right]$$

Passo 2. Para \(b = 1, \ldots, B\): simular \(n\) observações a partir do modelo ajustado com \(k_0\) componentes — assumindo que o modelo nulo é o gerador verdadeiro. Isso preserva a estrutura dos dados mas força \(k = k_0\).

Passo 3. Para cada dataset bootstrap \(b\), ajustar ambos os modelos (\(k_0\) e \(k_1\)) e calcular \(\Lambda^{(b)}\). A coleção \(\{\Lambda^{(1)}, \ldots, \Lambda^{(B)}\}\) é a distribuição empírica do LRT sob \(H_0\).

Passo 4. Calcular o p-valor empírico com a correção de Davison & Hinkley (1997) para evitar p-valor exato zero:

$$p = \frac{\#\{b : \Lambda^{(b)} \geq \Lambda_\text{obs}\} + 1}{B + 1}$$

Passo 5. Aplicar sequencialmente: testar \(k_0 = 1\) vs \(k_1 = 2\); se rejeitar \(H_0\), testar \(k_0 = 2\) vs \(k_1 = 3\); e assim por diante. O primeiro \(k_0\) para o qual \(H_0\) não é rejeitada é o \(k\) escolhido.

Por que o BLRT funciona onde o BIC falha

O BIC usa uma penalidade fixa \(\log(n)\) por parâmetro — derivada de uma aproximação assintótica que pressupõe regularidade. O BLRT, ao simular a distribuição nula diretamente do modelo ajustado, captura a geometria real da superfície de verossimilhança naquele problema. Se o ganho de \(k_0\) para \(k_1\) for pequeno em escala absoluta mas improvável sob \(H_0\), o BLRT o detecta; o BIC não.

"The bootstrap LRT was the best-performing test across all simulation conditions examined. It showed consistently low Type I error rates and high power to detect the correct number of classes, outperforming BIC, AIC, and the Lo-Mendell-Rubin adjusted LRT in conditions with class overlap." Nylund, Asparouhov & Muthén (2007, p. 562) · Structural Equation Modeling, 14(4), 535–569

5 · Fluxo de seleção adotado nesta tese

Nenhum critério isolado é suficiente. O protocolo combina critérios de informação, teste formal e métricas de validade interna, seguindo Nylund et al. (2007) e Nagin (2005):

Etapa Critério O que mede Limitação conhecida Referência
1 BIC Ajuste penalizado por parcimônia Subestima \(k\) com sobreposição elevada Schwarz (1978)
1 ICL BIC + penalidade de sobreposição Sinaliza sobreposição, não \(k\) Biernacki et al. (2000)
1 AIC3 Penalidade intermediária (\(3p\)) Empírico; melhor que AIC em amostras medianas Bozdogan (1994)
2 BLRT Teste formal \(H_0: k_0\) vs \(H_1: k_0+1\) Computacionalmente custoso; \(B \geq 199\) McLachlan (1987); Nylund et al. (2007)
3 EN Entropia normalizada das posteriores Comparação apenas dentro do mesmo \(k\) Celeux & Soromenho (1996)
3 AvePP Certeza média de classificação por componente Limiar 0,70 é convencional Nagin (2005)
4 ARI bootstrap Estabilidade a perturbações amostrais Sensível ao número de replicações Hubert & Arabie (1985)
Regra de decisão: o \(k\) é escolhido como o mais votado entre BIC, ICL, AIC3 e BLRT. Em caso de empate, o BLRT tem precedência — é o único com controle formal de erro tipo I. A decisão final é condicionada a EN \(\geq 0{,}80\) e AvePP\(_{\min} \geq 0{,}70\).

6 · Métricas de validade interna

Entropia normalizada (EN)

A forma normalizada de Celeux & Soromenho (1996) escala a entropia de Shannon para \([0,1]\) independentemente de \(k\):

$$\text{EN} = 1 - \frac{-\displaystyle\sum_{i=1}^{n}\sum_{g=1}^{k} \hat{z}_{ig}\,\log \hat{z}_{ig}}{n \cdot \log k}$$

EN = 1 indica classificação MAP perfeita (\(\hat{z}_{ig} \in \{0,1\}\)); EN = 0 indica probabilidades uniformes (máxima sobreposição). Limiar recomendado: EN \(\geq 0{,}80\).

AvePP — Probabilidade posterior média por componente

$$\text{AvePP}_g = \frac{1}{|\mathcal{C}_g|} \sum_{i \in \mathcal{C}_g} \hat{z}_{ig} \qquad \mathcal{C}_g = \{i : \hat{g}_i = g\}$$

Nagin (2005) recomenda AvePP \(> 0{,}70\) por componente. Valores menores indicam que a componente está absorvendo indivíduos de outras — sinal de sobreposição excessiva ou \(k\) superestimado.

7 · Estabilidade via bootstrap ARI

Um \(k\) que satisfaça BIC/BLRT e as métricas de validade interna ainda pode ser instável: perturbações amostrais pequenas podem produzir soluções muito diferentes. O bootstrap de estabilidade quantifica isso:

  1. Amostrar com reposição \(B\) vezes de \(y_1, \ldots, y_n\).
  2. Para cada réplica, ajustar o modelo com o \(k\) escolhido.
  3. Calcular o ARI entre a classificação MAP da réplica e a classificação MAP original.

O Adjusted Rand Index (Hubert & Arabie, 1985) mede concordância entre duas partições corrigindo pelo acaso: ARI = 1 para concordância perfeita, ARI ≈ 0 para concordância aleatória. Critério adotado: ARI médio \(\geq 0{,}80\).

ARI médio \(< 0{,}80\) não implica que \(k\) está errado. Pode indicar que os grupos existem mas se sobrepõem tanto que a classificação MAP é sensível ao conjunto de treinamento — esperado em dados de utilização em saúde com \(\theta\) pequeno. O modelo mantém valor descritivo; a classificação individual deve ser tratada com cautela.

O pareamento entre componentes estimados e grupos verdadeiros é feito pelo algoritmo húngaro, que maximiza a acurácia global sob a melhor correspondência possível.

Acurácia global vs. sensibilidade por grupo. A acurácia global é \(\sum_g \text{TP}_g / n\). A métrica por grupo — denominada aqui sensibilidade ou acurácia marginal — é \(\text{sens}_g = \text{TP}_g / n_g\), onde \(n_g\) é o total de observações verdadeiras do grupo g. Ela responde: "de todos os beneficiários que realmente pertencem ao grupo G, quantos foram corretamente identificados?" Essa é a definição de recall por classe — distinta da acurácia, que incluiria verdadeiros negativos e não faz sentido marginalizada por grupo em problemas multiclasse.

Log-verossimilhança oráculo

# Teto teórico: logLik calculada com os parâmetros verdadeiros
ll_obs <- function(y, mus, thetas, pis) {
  k  <- length(mus)
  lp <- sapply(1:k, function(h)
    log(pis[h]) + dnbinom(y, size = thetas[h], mu = mus[h], log = TRUE))
  m <- apply(lp, 1, max)
  m + log(rowSums(exp(lp - m)))   # log-sum-exp estável
}
ll_oraculo <- sum(ll_obs(consultas,
  mus = mu_grupos, thetas = rep(theta_nb, 4), pis = pi_grupos))

ll_melhor_k <- function(df_b, k, modelo_b, nrep) {
  best <- -Inf
  for (i in seq_len(nrep)) {
    m <- tryCatch(
      suppressWarnings(flexmix(consultas ~ 1, data = df_b, k = k,
        model = modelo_b,
        control = list(iter.max = 200, minprior = 0.01, tolerance = 1e-6))),
      error = function(e) NULL)
    if (!is.null(m) && m@k == k) {
      ll <- as.numeric(logLik(m))
      if (!is.na(ll) && ll > best) best <- ll
    }
  }
  if (is.infinite(best)) NA_real_ else best
}

blrt_passo <- function(fit_k0, fit_k1, n_obs, B = BLRT_B,
                       nrep = BLRT_NREP, theta_fixo = NULL, seed = NULL) {
  if (!is.null(seed)) set.seed(seed)
  k0      <- fit_k0@k;  k1 <- fit_k1@k
  lrt_obs <- 2 * (as.numeric(logLik(fit_k1)) - as.numeric(logLik(fit_k0)))
  modelo_b <- FLXMRnegbin(theta = theta_fixo)

  lrt_b <- vapply(seq_len(B), function(b) {
    y_b  <- simular_nb_mistura(fit_k0, n_obs, theta_fixo = theta_fixo)
    df_b <- data.frame(consultas = y_b)
    ll0  <- ll_melhor_k(df_b, k0, modelo_b, nrep)
    ll1  <- ll_melhor_k(df_b, k1, modelo_b, nrep)
    if (anyNA(c(ll0, ll1))) NA_real_ else 2 * (ll1 - ll0)
  }, numeric(1))

  lrt_v <- lrt_b[!is.na(lrt_b)]
  pval  <- (sum(lrt_v >= lrt_obs) + 1) / (length(lrt_v) + 1)
  list(k0=k0, k1=k1, lrt_obs=round(lrt_obs,2),
       pval=round(pval,4), B_valid=length(lrt_v), lrt_boot=lrt_v)
}

Confronto k = 3 vs k = 4 — algoritmo húngaro e sensibilidade

# Algoritmo húngaro: pareamento ótimo componentes -> grupos.
# conf_mat: nr x nc (linhas = grupos reais, colunas = componentes).
# Retorna assignment[g] = coluna de conf_mat para grupo g (NA se sem componente).
# Implementação em base R (permutação exaustiva, k ≤ 8 → 40320 perms, trivial).
hungarian_match <- function(conf_mat) {
  nr <- nrow(conf_mat); nc <- ncol(conf_mat)
  k  <- max(nr, nc)
  sq <- matrix(0L, k, k)
  sq[seq_len(nr), seq_len(nc)] <- conf_mat
  perms  <- perms_all(k)
  scores <- apply(perms, 1L, function(p) sum(diag(sq[, p, drop = FALSE])))
  a      <- as.integer(perms[which.max(scores), ])
  ifelse(a[seq_len(nr)] <= nc, a[seq_len(nr)], NA_integer_)
}

avaliar_modelo <- function(nome, fit) {
  k      <- fit@k;  k_true <- nlevels(df$grupo_real)
  conf   <- table(real = df$grupo_real,
                   est  = factor(clusters(fit), levels = seq_len(k)))

  # Algoritmo húngaro
  assgn  <- hungarian_match(conf)    # assgn[g] = coluna de conf para grupo g

  # Matriz pareada: colunas reordenadas para alinhar com grupos verdadeiros
  cm <- matrix(0L, k_true, k_true,
               dimnames = list(real = rownames(conf),
                                grupo_map = rownames(conf)))
  for (g in seq_len(k_true))
    if (!is.na(assgn[g])) cm[, g] <- as.integer(conf[, assgn[g]])

  # Acurácia global
  acc <- 100 * sum(diag(cm)) / sum(cm)

  # Sensibilidade por grupo: sens_g = TP_g / n_g (recall por classe)
  n_g  <- rowSums(cm);  tp_g <- diag(cm)
  sens <- ifelse(is.na(assgn), 0, 100 * tp_g / n_g)

  cat(sprintf("\n[%s]  acuracia=%.1f%%  EN=%.3f  AvePP_min=%.3f\n",
              nome, acc, metricas_validacao(fit)$EN,
              metricas_validacao(fit)$AvePP_min))
  print(cm)
  for (g in seq_len(k_true))
    cat(sprintf("  G%d: %5.1f%%  [%d/%d]\n", g, sens[g], tp_g[g], n_g[g]))
  invisible(list(conf=conf, cm=cm, acc=acc, sens=sens, assgn=assgn))
}
Detalhe de implementação crítico: o helper ll_melhor_k() usa flexmix() diretamente, não stepFlexmix() + getModel(). O motivo: stepFlexmix pode colapsar uma componente (minprior) e retornar k_efetivo < k_solicitado; nesse caso getModel(m, which = "4") lança erro, fazendo todos os B replicados retornarem NA (B_valid = 0), com p-valor espúrio de 1,0. A guarda m@k == k descarta replicados colapsados e evita o falso não-rejeito.
